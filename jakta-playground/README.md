# Evaluation

## Prerequisites

Before starting, make sure you have JDK 21 or newer installed.

To test the online scenario, [Docker](https://docs.docker.com/engine/install/) and [Docker Compose](https://docs.docker.com/compose/install/) need to be installed too.

## Deployment

The deployment for the offline scenario requires issuing the following commands:

```bash
git clone https://github.com/pikalab-unibo-students/master-thesis-battistini-ay2425
git checkout feat/jakta-sifting-patterns
./gradlew build
```

The online scenario uses a centralized logging system, based on the [ELK stack](https://www.elastic.co/elastic-stack/) (with Opensearch in place of Elastic).

To deploy the single-node cluster in development mode, a docker compose file can be used:

```bash
cd jakta-toolbox/infra
docker compose up
```

The docker compose file will build an extended version of Logstash with the plugin to work with OpenSearch.

In addition, it will read the configuration of the instance from the `logstash.conf` file on the filesystem, it will bind ports 9200 and 4054–4056 and create a volume to store the opensearch data.

## Usage examples

Since the matching of the sifting patterns can be performed both online and offline, an example is given below for each of the two scenarios.

### Online scenario

To perform pattern matching in an online manner, make sure to deploy the ELK cluster as outlined before, then start the Ktor application that will perform the enrichment of the logs.

Finally, once the server is ready, the domestic robot application can be started.

```bash
./gradlew matchStream
./gradlew runDomesticRobot --args="--log-to-server --log-to-file"
```

This will produce a set of logs that will be stored in the OpenSearch instance and printed on console by the `matchStream` task.

To print the stored logs on stdout, the following Gradle task can be run:

```bash
./gradlew analyzeIndex --args="--mas-id <id> --implementation-level"
```

Where the `--mas-id` and `--agent-id` options require the UUIDs generated by the execution of the `runDomesticRobotSample` task and available by reading the file names of the log files written under the `jakta-playground/logs` directory.

To see the logs generated by a specific agent, use the `--agent-id` option.

If the option is omitted, then the logs generated by each agent and by the environment are shown.

To see the logs generated by the pattern-matching, the following task can be used:

```bash
./gradlew analyzeIndex --args="--mas-id <id> --domain-level"
```

### Offline scenario

Pattern matching in the offline manner requires running the following Gradle task:

```bash
./gradlew runDomesticRobot --args="--log-to-file --log-to-single-file"
# substitute <id> with the id in the filename of the log file generated by the previous run
./gradlew matchFile --args="--log-to-file --match-file '$PWD/jakta-playground/logs/trace-<id>.jsonl'"
```

The first task will print to the console the log events generated by the mas execution and write them in the `jakta-playground/logs` directory.

The second task will print to the console the new log events generated by the pattern matching and write them in the `jakta-playground/logs` directory.
